## Sprint intent

Sprint 23 introduces an explicit deterministic knowledge graph so discoveries, inventions, and applications become a progression system instead of loosely related event categories.

## Why this sprint comes next

The existing simulation already emits discoveries and inventions, but it does not yet own a stable progression graph or application layer. After goals are in place, the next backend foundation is the knowledge system that later unlocks new action families.

## Sprint outcome

At the end of Sprint 23, HUMANAIty can load a versioned `tech-tree.json`, evaluate prerequisites deterministically, unlock discoveries, inventions, and applications over time, and expose the resulting progression through backend read models.

## Sprint scope

### In scope

- Define the `tech-tree.json` schema for discoveries, inventions, and applications.
- Add config loading and validation for stable knowledge ids and prerequisite references.
- Evaluate unlock rules deterministically from persisted events and prior knowledge state.
- Persist or derive application unlock state in a way that supports later action scheduling.
- Expose the knowledge graph and unlocked state through APIs/read models needed by UI and MCP.

### Out of scope

- Full content authoring for a large tech tree.
- New action execution behaviors from unlocked applications.
- Tribe-specific knowledge exchange.

## Product and technical decisions for this sprint

- **Decision 1:** The tech tree is configuration-backed, versioned, and deterministic; it is not generated by the LLM.
- **Decision 2:** Unlock evaluation must be derived from canonical simulation state and persisted events, not from frontend interpretation.
- **Decision 3:** Applications unlock capabilities, but Sprint 23 stops at unlock state and read-model exposure.

## Deliverables

- `tech-tree.json` schema and initial seed content.
- Deterministic unlock evaluation for discoveries, inventions, and applications.
- Read-model/API exposure for knowledge progression.

## Definition of done

- The backend can load and validate `tech-tree.json`.
- Discoveries can unlock inventions, and inventions can unlock applications, using deterministic prerequisite evaluation.
- Same seed and same event history produce the same unlocked knowledge state.
- UI and MCP consumers can read unlocked knowledge state without LLM dependency.

## Features and task breakdown

### Feature 1: Tech-tree schema and loader

**Goal:** Make knowledge progression configuration explicit and validated.

**Acceptance criteria:** `tech-tree.json` schema defined; loader validates ids, node types, and prerequisites; initial seed content added.

**Best owner:** Codex.

### Feature 2: Deterministic unlock evaluation

**Goal:** Progress from discovery to invention to application using rule-based prerequisite checks.

**Acceptance criteria:** Unlock evaluation is deterministic; source event and prerequisite mapping is clear; application unlock state available for later use.

**Best owner:** Codex.

### Feature 3: Read-model exposure

**Goal:** Make knowledge progression visible without making the frontend infer it.

**Acceptance criteria:** Snapshot, overview, timeline, or MCP read surfaces can expose unlocked knowledge state and recent progression changes.

**Best owner:** Codex.
